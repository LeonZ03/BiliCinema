# BiliCinema Android

原生 Java 安卓客户端，支持 Android 8 及以上手机、平板。首页、观影、房间和聊天由原生界面呈现；Media3 播放本机解析的媒体，Android System WebView 用于独立的 B 站官方登录页和需要官方授权的受保护影片。APK 不包含视频下载或离线观看功能。

## 播放与账号

粘贴 BV/av 编号、带 p 参数的视频链接、ep 剧集链接或 B 站 App 的整段分享文字。分享文字优先提取官方链接，忽略标题和推荐语；b23.tv/ep、BV、av 这类完整影片编号链接直接在本机转换为对应官方网页链接，无需访问短链服务；随机短码仍安全展开真实跳转，分 P 只取目标链接自身的参数。也可通过 Android 系统分享将文字填入选片框，再选择打开或建房。BilibiliMediaResolver 在本机解析精确 aid/bvid/cid/episode 身份，使用普通视频 WBI 或番剧 v2 播放接口取得当前账号可用的媒体。MediaSession 拥有选择代次、已解析身份和播放器源绑定；旧选择、旧请求和旧播放器回调不能发布到新影片。

普通片源使用 Media3 播放完整授权的 H.264/AAC DASH 音视频分离流及单段 MP4。完整授权响应若带 DRM 标记，改由内嵌的 B 站官方播放器处理播放和授权，页面只显示视频，继续使用应用的控制栏和聊天。只传入公开影片页，复用本机 CookieManager 会话；不提取许可证或密钥。适配层核对实际 cid/episode、可用状态和时长，试看、预告或身份不符不会发布房间就绪。官方网页与官方 App 的授权、设备支持可能不同，不能保证全部会员内容可播；失败仍可在官方 App 打开。换片先清除旧时长，解析后立即显示新标题，失败不会继续显示上一部影片的信息或把未准备的影片标为就绪。

播放控制栏提供本机清晰度选择和倍速。原生清晰度仅列出播放接口实际返回的兼容轨道/完整单段 MP4 档位，不把宣传的会员画质直接视为可用；原生自动模式选择最高可用画质。官方播放列出授权响应提供的档位，实际画质由官方播放器回报；自动模式沿用官方播放器的选择。切换会重新获取本机片源并保留进度、倍速及播放/暂停意图；偏好保存在本机，后续影片若没有对应档位会显示实际回退画质。房间成员可各自选画质，访客重载只影响本机，房主重载仍按既有就绪规则短暂等待后恢复。

当前影片的分 P 或番剧剧集可从选集入口查看；目录来自已解析的官方影片页/番剧季数据，访客也可浏览，切换仍遵循房主权限和房间同步规则。非全屏控制栏仅保留画质与倍速；全屏将弹幕、字幕、选集等操作合并为一行。字幕目录异步读取；只在用户选择语言后下载该轨道正文，按播放时间呈现，目录为空时提示“此视频没有可选字幕”，加载失败可重试。滚动弹幕按六分钟分段异步加载 protobuf 数据并限制内存条数，按播放位置呈现；加载中、无弹幕、加载失败会分别提示，失败可重试。弹幕和字幕只影响本机，访客也可自行设置。API 请求只向 B 站主域发送本机 Cookie，字幕正文只从受信 B 站字幕域读取且不携带 Cookie。换片和后台暂停取消旧轨道请求，拖动进度切换对应弹幕分段，不阻塞影片准备。影片自带的画面内字幕不属于可选字幕轨道，无法通过字幕开关去除。

登录页先验证既有 CookieManager 会话，已登录时显示原生账号卡片、UID 和头像，不显示 B 站首页。头像单独从 B 站图片域加载，不携带登录 Cookie，加载失败仍保留已验证的登录状态与 UID。未登录时默认生成官方扫码登录二维码，显示等待扫码、等待确认、过期和可恢复错误；“复制二维码图片”将本机 PNG 放入系统剪贴板，返回或切换应用后仍可粘贴。私有图片由同一存储 owner 在首次写入前登记，最多保留五分钟，过期后不再提供读取。需要时可切换至官方网页登录，成功后自动收起网页。

二维码请求使用隔离会话，候选登录通过 nav 验证后才写入本机 CookieManager。进程级 LoginCookieCommit 串行拥有完整写入批次，等待全部回调、flush 与相同账号读回验证后才显示成功；退出页面只移除观察者，不能放弃已开始的写入。等待提示不会提前释放提交所有权；CookieManager 本身不提供原子多 Cookie 事务，进程重启后始终重新验证。TLS 失败取消请求，WebView 进程退出后允许重试。Cookie 不进入房间协议，API 禁止自动重定向；原生媒体 CDN 请求只附带 Referer/User-Agent，不转发 API Cookie；官方播放器的请求由 WebView 自身处理。错误文案使用固定分类，不展示二维码凭据、签名媒体 URL 或原始网络异常。

PlaybackAdapter 统一设备播放器回调契约。NativePlaybackAdapter 拥有 Media3 播放器，OfficialPlaybackAdapter 拥有官方页面与轮询资源；二者均沿用 MediaSession 的代次和准备状态，PlaybackIntentState 拥有播放意图与系统抑制状态。官方页面的音频焦点由 WebView 管理，适配层不重复申请；播放请求因加载/跳转而取消时不会误报为用户手势阻止。远端快照的暂停、跳转和倍速不会重新发成房主操作。短暂缓冲与系统焦点抑制、永久焦点丢失、明确本地点按分别处理。快速换片、返回首页和销毁会取消旧请求并释放旧播放器。

HttpResourceLifecycle 统一跟踪后台网络取消和关闭，TLS 连接池释放不在界面线程执行。操作代次同步失效，取消队列与可能阻塞的 TLS 清理队列分离；页面重建、换片、退出和登录取消沿用同一关闭规则，清理失败只记录固定安全信息。

用户创建或加入房间后，由 RoomSessionService 前台服务拥有 RoomClient 连接和有界的界面回放缓存，通知栏提供返回与退出入口。切到其他应用不销毁房间连接；观看 Activity 重建时重新绑定同一连接，读取最新服务端快照及最多 150 条内存聊天，不重复建房或入房。后台暂停本机视频，回到前台后按房间时间轴恢复。退出、结束房间或连接失败会撤下常驻通知；服务不会在进程被系统终止后自行创建新房间。通知权限可在首次进入房间时授予。

## 房间与同步

客户端直接连接 wss://bilicinema.leonz03.dpdns.org/v2/ws，邀请带 room 查询参数。房间最多五人，只有房主控制选片、进度、播放、暂停和倍速。云端以房主决定的时间轴为权威：

创建、加入、恢复和重连显示真实阶段：连接云端、发送请求、等待房间信息、同步状态、完成，以及已用时间。WebSocket 打开或请求进入队列不代表完成，必须收到有效成员凭据和房间快照并应用后才成功。失败保留中断步骤，可重试或取消；已获得凭据的重试继续原房间，避免重复建房。

- 访客加入、未就绪、缓冲、后台或断线只影响其本机，不暂停房主或其他访客。
- 访客恢复可播后对齐房主的当前进度，卡顿期间的片段会被跳过。
- 房主缓冲或未就绪时暂停全房，保留先前播放请求；主动暂停会清除该请求。
- 房主断线暂停，沿用重连窗口，恢复连接后重新确认播放。
- 成员就绪状态如实展示。ready=false 不能用来阻塞其他访客，也不能伪装成已就绪。

MediaIdentity 根据时间锚点与倍速估计当前位置。只有首次绑定、明确同步及足够大的误差才跳转，不能在每次 READY 或每次快照中反复强制 seek。

精确片源绑定后立即保留房主的播放/暂停意图，加载完成才对齐播放进度；不能等待 READY 才请求播放，否则需要先起播才能继续加载的官方影片会相互等待。加载期间的暂停覆盖此前的播放请求。官方影片尚未取得时长时仍属于加载中，已确认的试看或错误身份继续拒绝，只有完整影片实际可播才报告就绪。

播放器的实际进度和播放状态每秒与最新房间时间轴核对，即使没有新快照，也会纠正意外暂停或进度偏差。加载、后台和明确的系统播放阻止不会被当作已同步；持续十秒未能对齐会显示重新同步入口，恢复后自动收起。官方页面重建时重新应用保留的播放意图；系统要求手动启用时，本机操作只解除本机阻止，不改变房主时间轴。

## 界面与聊天

首页使用与 Windows 一致的白色、浅灰与蓝色，支持跟随系统、浅色和深色外观；观影保持深色。主页提供影片输入、精简预览、播放、创建及加入房间；有效房间可恢复。影片预览只使用解析器返回的标题、时长和公开封面，封面无凭据且有大小限制，预览失败不阻塞正式播放。账号入口集中头像、昵称、UID 复制、更新检查、外观及切换/退出登录。

默认保持竖屏布局，以 16:9 视频和下方聊天为主，成员列表从顶部人数图标打开。点全屏根据播放器实际视频宽高主动选择方向：横向影片允许左右两种横屏方向，竖向影片允许正反两种竖屏方向，不依赖系统自动旋转开关；退出全屏回到竖屏布局。尺寸尚未就绪时保留当前方向。全屏状态由显式操作持有，配置或键盘变化不会将其重新解释为横竖屏状态。旋转配置由 Activity 原地处理，开关聊天不会销毁或重建播放器。原生与官方播放器都通过同一回调上报画面比例，过期影片回调不能改变方向。官方播放器的视频视口随设备宽度适配，并固定页面缩放，防止旋转后沿用旧倍率裁切画面；操作和无障碍控件仍由原生界面提供。宽窗口的平板布局支持视频与聊天分栏。加入、换片、清晰度和倍速使用底部面板，输入支持粘贴、清除与关闭后保留草稿。房间邀请可以包含分享文案，只从原服务域名提取房间码。图标提供无障碍名称，触控区域至少 48dp。

影片链接、房间邀请和昵称输入框有内容时显示清除按钮，一次点按清空并保留输入焦点；空内容时隐藏按钮。

全屏单击视频右侧空白区域可呼出聊天，避开系统边缘、进度和播放控件；双击、长按和滑动不打开聊天。横屏侧栏约占三分之一，窄屏全屏改为下方面板。全屏视频占据稳定的窗口区域，系统栏、屏幕缺口和键盘仅影响上层控件与聊天面板的避让；打开或关闭聊天、弹出或收起键盘不会缩放或平移视频。点击外部一次关闭聊天与键盘，该点击不穿透触发播放操作。打开聊天不自动弹键盘，未发送草稿保留。返回键依次收键盘、关聊天、退全屏。保留聊天图标和关闭按钮作为可访问入口。

收到其他成员消息时，右侧短暂显示昵称与消息内容，和 Windows 一致；点击预览可打开聊天。预览采用有界队列，不自动展开抽屉，聊天已打开时不重复提示。只支持文字，发送成功才清空输入并继续保留输入焦点；新消息滚动不抢走键盘焦点。键盘只调整聊天可用区域，视频位置与尺寸保持固定。全屏聊天采用透明背景，点击外部只关闭聊天与键盘，下一次点击视频才打开播放控制栏。房间昵称独立于 B 站账号，不自动公开账号身份。聊天只保存在当前房间内存，离开房间后清除。

弹幕开关是各成员的本机偏好，房主也不例外；保存到本机设置，不发送房间命令，不改变其他成员的弹幕或播放状态。

## 构建、签名与更新

使用 JDK 17、Android SDK 35 和仓库内 Gradle wrapper：

    pwsh -File script/build-android.ps1

脚本运行 release unit tests、lint 和签名组装，输出 artifacts/releases/<version>/android/BiliCinema-<version>-android-universal.apk 及 SHA256SUMS.txt。版本与 versionCode 派生自根目录 version.txt。SkipChecks 仅用于本地迭代，不能作为正式发布验收。

CI 使用 BILICINEMA_KEYSTORE、BILICINEMA_KEY_ALIAS、BILICINEMA_KEYSTORE_PASSWORD、BILICINEMA_KEY_PASSWORD。保留首次发布身份；本机 android/.keys 不得重新生成、提交或打印。不同签名不能覆盖现有安装。

更新从 `https://bilicinema.leonz03.dpdns.org/downloads/android-manifest.json` 检查版本，并从同域直接下载 APK，不依赖 GitHub Release。校验清单中的大小和 SHA-256、包名、更高版本码及原签名后交给系统安装器；安装权限与系统确认仍需用户操作。UpdateJournal 在首次写入前持久记录更新文件与阶段，处理中断恢复和已完成安装清理；失败保留原安装与用户设置。发布步骤见 cloud/DEPLOYMENT.md。
