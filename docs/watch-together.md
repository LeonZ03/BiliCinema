# 观影使用说明

## 页面

- **登录**：用哔哩哔哩 App 扫码；完成后显示昵称、UID 和会员状态。
- **在线播放**：粘贴 B 站电影或番剧剧集链接，解析并开始播放。播放器的画质、音量、进度、播放暂停、倍速和全屏按钮均可直接使用。
- **观影房间**：有独立的影片链接输入，不会覆盖“在线播放”页的链接。房主解析影片后点“创建房间”，软件在房主电脑启动仅监听 `127.0.0.1:5077` 的房间服务，自动生成 Cloudflare Quick Tunnel 邀请。另一台电脑粘贴邀请加入；房主可直接在视频画面内控制播放、进度和倍速。
- **下载影片**：使用原 DownKyi 下载页面及下载器。

创建房间时房主在本机直接连接本机服务，对方通过邀请中的 `wss://…trycloudflare.com/ws` 连接。每台电脑都从 B 站独立取流，Cloudflare 只转发房间控制消息。房主退出软件会结束本机 Tunnel；下次创建的临时地址会不同。

加入者若勾选“加入时使用房主账号”，自己的电脑会生成 B 站登录二维码，经过房间服务转发给房主显示。房主用自己的哔哩哔哩 App 扫码确认；加入者电脑自行向 B 站查询并保存登录状态，原有本机登录在验证成功后被替换。房间服务和房主软件均不会收到加入者的 Cookie。二维码过期时，加入者可点“重新请求房主扫码”。

## 同步方式

服务端使用单调计时器推进房间影片位置，并广播选片、播放、暂停、跳转、倍速和双方缓冲状态。客户端约每秒读取本机网页播放器进度，约每五秒用 ping 测往返延迟并估计与服务端的时钟偏移。双方不持续上传真实播放位置作两两比较。

时间差在 0.45 秒内不做位置校正；0.45–1.5 秒时暂时把播放速度最多调整 4%；超过 1.5 秒才直接跳转。明确拖动进度条造成的大跳转会立即传播。Cloudflare 的延迟主要影响控制到达时间和时钟估计；普通控制消息很小，当前 Quick Tunnel 已足够用于临时双人观影。固定私有域名的主要收益是邀请地址稳定，仍然经过 Cloudflare，不能保证更低延迟。

如果一方正在缓冲，服务端暂停双方，待都准备好后继续。画质、音轨、音量和全屏是每台电脑各自选择的。B 站可用画质还取决于账号权限、影片和设备。

## 构建与验证

开发电脑运行 `Build-BiliCinema.cmd` 生成单文件 EXE；目标电脑只需复制该 EXE。播放需要 Windows WebView2 Runtime。房间服务也可作为独立 .NET 项目运行以便协议测试，详见 [房间服务说明](../src/DownKyi.RoomServer/README.md)。

当前已经由使用者在两台异地电脑完成基本播放和入房试用；新的柔性同步、网页按钮控制、协助登录与单文件下载入口仍应继续用两台真实账号设备回归，尤其要检查长时间播放、进度条跳转、二维码过期和重新连接。
