# 观影使用说明

## 页面

- **账号**：用哔哩哔哩 App 扫码；完成后显示头像、昵称、UID 和会员状态，支持复制 UID 和二维码。
- **观影房间**：粘贴 B 站电影、番剧剧集或普通视频链接，解析后上方会加载暂停的视频画面，不必先创建房间。播放、暂停、画质、音量、进度、倍速和全屏均在视频内操作。需要邀请好友时点“创建房间”；Windows 和 Android 均直接连接 Cloudflare 上的房间服务，不需要本地服务或 Tunnel。最多 4 位好友可粘贴同一个邀请加入，含房主共 5 人；页面显示当前房间人数。
- **下载**：沿用 DownKyi 原有界面，左侧切换正在下载和已完成，保留暂停、继续、删除、打开目录及批量操作。与观影共用本机登录，入口标注“来自 DownKyi”。

所有成员通过 `wss://bilicinema.leonz03.dpdns.org/v2/ws?room=…` 连接同一个云端房间。每台设备独立从 B 站取流，Cloudflare 只处理控制和聊天。房主结束或离开房间使旧邀请失效；短暂断网暂停房间，保留 2 分钟重连窗口。访客断线保留身份 5 分钟，满员时可让出离线席位。云端自动清理，单间最长保留 24 小时。

创建按钮显示连接云端、创建房间、同步影片的步骤和耗时。网络或额度问题会显示错误，可稍后重试；无需在客户端安装 cloudflared。账号页显示当前程序版本。

Windows 窗口模式使用右侧聊天栏，顶部聊天图标可开关；全屏聊天覆盖在视频上，鼠标移到视频右侧边缘即可呼出，移开后自动收起，正在输入或有草稿时保持展开。也可点击聊天按钮打开，点击外部、关闭按钮或按 Esc 收起。聊天开关不改变全屏画面尺寸，也不触发播放暂停。输入框按 Enter 发送；输入和选字期间保留焦点。新消息仍在视频右侧显示 5 秒。播放器下方的网页弹幕发送栏隐藏，画面弹幕仍可使用。聊天记录只保存在当前软件运行内存中；离开或结束房间会清除本机记录，后来加入的人不会收到之前的聊天。

如果需要别人帮忙扫码登录，请在需要登录的电脑上打开“登录”页，获取二维码后点击“复制二维码图片”，再通过私下渠道发送图片。图片包含二维码和 BiliCinema 标识。对方用哔哩哔哩 App 扫码确认后，软件会在本机完成登录；二维码过期则重新获取并发送。房间服务不参与登录。

### 已确定的界面与交互

- 首页、下载、账号使用图标导航；设置从账号页或原下载首页进入。首页的视频和房间输入均可一键清空、粘贴；先单人播放或先建空房均可。
- 观影页保留视频、房间人数、邀请、聊天和换片；昵称、离开或结束房间、连接详情位于更多菜单。
- 返回首页不会重建播放器。窗口聊天栏与全屏覆盖层共用房间消息；全屏聊天边缘避开播放器底部控制区。
- 结束房间仅限房主；访客可自行离开，不能更改房主的影片和播放进度。
- 新聊天消息在画面右侧提示 5 秒；房主的播放操作在左侧逐条提示，每条保留 1 秒。
- Logo 原始定稿为 [方案 A](assets/logo-a-approved.png)；程序图标、侧栏和二维码分享卡片直接使用原图提取的同一标识，不能重新绘制或改变比例、颜色。转换方式见[维护文档](maintenance.md#品牌资源)。

这些约定与实际 UI 代码共同替代早期预览图；软件不需要设计稿、浏览器试验数据或旧 exe 才能构建。

## 同步方式

每次房主的播放器准备好后，软件会读取实际进度、倍速和播放状态，显式同步一次；
包括 B 站恢复的历史进度。同步状态右侧的 **↻** 按钮始终显示：点击会检查并尝试恢复
播放器操作栏；房间内还会执行同步，房主向房间发送当前状态，访客立即对齐房主。
单人观看时仅检查播放器，未解析视频时会提示先解析。检查操作不重新加载视频，
也不改变单人或房主的进度、倍速及暂停状态。房间成员应使用同一版本的软件。

播放器恢复会通过 B 站播放器自身的模式接口退出误触发的小窗，再验证控制栏的位置和可点击性。
只调整外观尺寸不能恢复小窗状态下被播放器隐藏的操作栏；切集替换播放器后也需要重新绑定检查。

云端使用保存的进度、时间戳和倍速推算影片位置，并广播选片、播放、暂停、跳转、倍速和所有成员的缓冲状态。客户端约每秒读取本机网页播放器进度，约每三十秒用 ping 测往返延迟并估计与服务端的时钟偏移。访客各自将本机进度与房间进度比较，不需要在成员之间两两比对。

时间差在 0.45 秒内不做位置校正；0.45–1.5 秒时暂时把播放速度最多调整 4%；超过 1.5 秒才直接跳转。明确拖动进度条造成的大跳转会立即传播。Cloudflare 的延迟主要影响控制到达时间和时钟估计；普通控制消息很小，多人使用时仍只转发小体积的控制和聊天消息，实际连接质量取决于网络和 Cloudflare 服务。固定私有域名的主要收益是邀请地址稳定，仍然经过 Cloudflare，不能保证更低延迟。

房间使用房主主导的时间轴：访客加入、加载、缓冲、切后台、离开或断线都不暂停其他人。访客恢复后对齐房主当前进度，卡顿期间的片段可能跳过。只有房主未就绪或缓冲才暂停全房，保留此前播放请求；房主主动暂停后保持暂停，断线重连后重新确认播放。画质、音轨、音量和全屏是本机选项，实际能力取决于账号权限、影片和设备。

Android 使用原生观影界面和 Media3，官方登录独立成页。全屏点击视频右侧空白区打开聊天抽屉，点击外部关闭抽屉与键盘并保留草稿，不触发播放。新消息在右侧显示昵称与内容短预览，不自动展开聊天；平板可常驻房间侧栏。具体操作与媒体支持范围见 [Android 说明](../android/README.md)。

## 构建与验证

开发电脑运行 `build-windows.cmd` 生成单文件 EXE；目标电脑只需复制该 EXE。播放需要 Windows WebView2 Runtime。Android 构建与设备验收见 [Android 说明](../android/README.md)。云端部署见 [Cloudflare 说明](../cloud/DEPLOYMENT.md)；保留的独立 .NET 服务用于本地开发和协议测试，见 [房间协议](../src/DownKyi.RoomServer/README.md)。

五人房间回归覆盖人数上限、全体广播、缓冲等待、单个成员离开及重连。实际异地网络与 B 站账号权限仍应使用真实设备验证。
