# 观影使用说明

## 页面

- **登录**：用哔哩哔哩 App 扫码；完成后显示昵称、UID 和会员状态。
- **观影房间**：粘贴 B 站电影、番剧剧集或普通视频链接，解析后上方会加载暂停的视频画面，不必先创建房间。播放、暂停、画质、音量、进度、倍速和全屏均在视频内操作。需要邀请好友时点“创建房间”；软件在房主电脑启动仅监听 `127.0.0.1:5077` 的房间服务，自动生成 Cloudflare Quick Tunnel 邀请。最多 4 位好友可粘贴同一个邀请加入，含房主共 5 人；页面显示当前房间人数。
- **下载影片**：使用原 DownKyi 下载页面及下载器。

创建房间时房主在本机直接连接本机服务，访客通过邀请中的 `wss://…trycloudflare.com/ws` 连接。每台电脑都从 B 站独立取流，Cloudflare 转发房间控制和聊天文字，不转发电影画面。房主结束或离开房间会释放本机服务和 Tunnel，退出软件同样会清理。立即重新创建会等待旧房间释放完毕，再生成新地址；需要重新复制邀请给好友。公网准备直接检查访客实际使用的 WebSocket 通道。加入失败会提示超时、网关不可用或房间已结束等原因。

创建按钮下方会显示步骤完成度百分比、当前步骤和已用时间。程序先创建本机房间，再准备公网邀请；网络等待和重试时保持当前值，失败后仍可点击创建房间重试公网邀请。公网准备直接验证访客实际使用的 WebSocket，并逐步延长重试间隔。左下角显示当前程序版本。

房间页面可设置聊天昵称。窗口和全屏模式下，把鼠标移到视频右边缘都会出现半透明聊天面板；未输入时移出面板 0.5 秒后收起，移回可取消。点击输入框或开始打字后，面板保持展开，选字或鼠标误移不会中断输入；按 Alt 收起并保留草稿。Alt 不触发暂停或全屏操作；右侧重新呼出后可继续编辑。面板内按 Enter 发送，按 Shift+Enter 换行，底部“Shift+Enter 换行”和“Alt 收起”各占一行。观看时，对方的新消息会在视频右侧短暂显示，5 秒后消失，全屏时同样可见。聊天记录只保存在当前软件运行内存中，不上传账号信息；离开或结束房间会清除本机记录，后来加入的人不会收到之前的聊天。

如果需要别人帮忙扫码登录，请在需要登录的电脑上打开“登录”页，获取二维码后点击“复制二维码图片”，再通过私下渠道发送图片。图片包含二维码和 BiliCinema 标识。对方用哔哩哔哩 App 扫码确认后，软件会在本机完成登录；二维码过期则重新获取并发送。房间服务不参与登录。

### 已确定的界面与交互

- 登录、观影、下载使用左侧导航；播放控制放在视频内，支持先单人播放或先创建空房间。
- “我的昵称”位于房间区域右上方并记住上次设置；服务地址只读，无房间时显示“暂无房间，待加入或创建”。
- 聊天面板为灰色半透明样式，窗口和全屏均从视频右边缘呼出；输入期间保持展开，Alt 收起，播放快捷键在面板收起后恢复。播放器布局自检在面板展开时暂停鼠标探测，避免干扰聊天。
- 聊天呼出边缘避开底部控制栏和右下角按钮，窗口与全屏一致。结束房间仅限房主；访客点击该按钮会得到提示并保留入房状态，可自行选择“离开房间”。
- 新聊天消息在画面右侧提示 5 秒；房主的播放操作在左侧逐条提示，每条保留 1 秒。
- Logo 原始定稿为 [方案 A](assets/logo-a-approved.png)；程序图标、侧栏和二维码分享卡片直接使用原图提取的同一标识，不能重新绘制或改变比例、颜色。转换方式见[维护文档](maintenance.md#品牌资源)。

这些约定与实际 UI 代码共同替代早期预览图；软件不需要设计稿、浏览器试验数据或旧 exe 才能构建。

## 同步方式

每次房主的播放器准备好后，软件会读取实际进度、倍速和播放状态，显式同步一次；
包括 B 站恢复的历史进度。同步状态右侧的 **↻** 按钮始终显示：点击会检查并尝试恢复
播放器操作栏；房间内还会执行同步，房主向房间发送当前状态，访客立即对齐房主。
单人观看时仅检查播放器，未解析视频时会提示先解析。检查操作不重新加载视频，
也不改变单人或房主的进度、倍速及暂停状态。房间成员应使用同一版本的软件。

播放器恢复会通过 B 站播放器自身的模式接口退出误触发的小窗，再验证控制栏的位置和可点击性。
只调整外观尺寸不能恢复小窗状态下被播放器隐藏的操作栏；切集替换播放器后也需要重新绑定检查。

服务端使用单调计时器推进房间影片位置，并广播选片、播放、暂停、跳转、倍速和所有成员的缓冲状态。客户端约每秒读取本机网页播放器进度，约每五秒用 ping 测往返延迟并估计与服务端的时钟偏移。访客各自将本机进度与房间进度比较，不需要在成员之间两两比对。

时间差在 0.45 秒内不做位置校正；0.45–1.5 秒时暂时把播放速度最多调整 4%；超过 1.5 秒才直接跳转。明确拖动进度条造成的大跳转会立即传播。Cloudflare 的延迟主要影响控制到达时间和时钟估计；普通控制消息很小，多人使用时仍只转发小体积的控制和聊天消息，实际连接质量取决于网络和隧道服务。固定私有域名的主要收益是邀请地址稳定，仍然经过 Cloudflare，不能保证更低延迟。

只有房主一人时，房主准备好就能播放；访客离开或断线后，其余在线成员可继续播放。访客在播放过程中加入时，服务端先暂停并等待访客准备好，再同步继续。如果任意在线成员正在缓冲，服务端暂停全房间，待所有在线成员都准备好后继续。画质、音轨、音量和全屏是每台电脑各自选择的。B 站可用画质还取决于账号权限、影片和设备。

## 构建与验证

开发电脑运行 `Build-BiliCinema.cmd` 生成单文件 EXE；目标电脑只需复制该 EXE。播放需要 Windows WebView2 Runtime。房间服务也可作为独立 .NET 项目运行以便协议测试，详见 [房间服务说明](../src/DownKyi.RoomServer/README.md)。

五人房间回归覆盖人数上限、全体广播、缓冲等待、单个成员离开及重连。实际异地网络与 B 站账号权限仍应使用真实设备验证。
