# DownKyi 仅观影与私人同步房间

## Windows 本地运行

1. 安装 .NET 10 SDK 和 mpv，在仓库根目录运行 `./script/start-watch.ps1 -MpvPath <mpv.exe完整路径>`。这个入口固定启动独立观影窗口，只有扫码登录、影片解析、轨道选择、播放器和房间控制；没有收藏、历史、个人空间或下载入口，也不会启动下载后台模块。
2. 第一次使用时扫码登录。粘贴 B 站番剧或电影链接，点“解析”。软件优先选择已解析到的 4K 轨道；若没有 4K，会提示并等待用户自己选择其他清晰度。
3. 点“在线播放 / 继续”。mpv 会在独立窗口打开视频，音轨由客户端自动加载。观影窗口显示播放器解码尺寸、已选编码和音轨。播放、暂停、拖动进度条或输入秒数跳转、倍速请使用观影窗口控制；mpv 窗口的音量和全屏只影响本机。
4. 房主在解析影片后点“创建房间”“复制邀请”。成员在自己的电脑启动同一个仅观影入口、扫码登录，粘贴邀请并点“加入房间”。成员本机重新解析同一剧集并打开自己的媒体连接，双方准备好后自动开始。房主控制暂停、恢复、跳转和倍速。
5. “离开房间”会停止本次播放，但不会退出 B 站账号。“退出本机账号”只清理这台电脑当前数据目录的登录状态。

测试两台本机客户端时，为每个实例指定不同目录：

```powershell
$mpv = 'C:\path\to\mpv.exe'
./script/start-watch.ps1 -DataDir ./artifacts/test-account-a -MpvPath $mpv
./script/start-watch.ps1 -DataDir ./artifacts/test-account-b -MpvPath $mpv
```

`DOWNKYI_DATA_DIR` 是已有的数据目录覆盖入口。只给测试实例使用独立目录，不会覆盖日常配置。原仓库的普通下载模式仍用原 `DownKyi.exe` 启动。

## 房间服务

本机联调启动 `./script/start-room-local.ps1`，默认地址为 `ws://127.0.0.1:5077/ws`。可用 `http://127.0.0.1:5077/health` 确认进程已启动。房间服务仅存储内存中的随机房间码、成员 ID、影片标识及播放状态；重启服务会结束所有房间。

异地使用时，将房间服务部署在你已授权的服务器上，保持服务自身只监听 `127.0.0.1:5077`，用支持 WebSocket 的 TLS 反向代理对外提供 `wss://你的域名/ws`。两端在观影窗口填同一个 `wss` 地址。`src/DownKyi.RoomServer/README.md` 给出 Caddy 示例、协议和连接限制。客户端拒绝对远程地址使用明文 `ws`。没有已授权服务器时，先本机联调，不把 `localhost` 联调当作异地验证。

## 画质、缓存与故障

- 4K 只在 B 站返回质量 ID 120 的真实轨道时显示并选中；播放器会报告实际解码尺寸。没有 4K 不会自动用低画质冒充。
- mpv 使用 `--cache-on-disk=no`、64 MiB demuxer 前向上限、16 MiB 后向上限和 20 秒预读；视频和外接音频各自可能占用缓存。播放不创建完整下载任务或影片文件。换片、停止和退出会终止托管播放器并释放缓存。
- 链接过期或播放中断时，客户端最多重新解析两次，尝试恢复原轨道与时间位置。若提示登录失效，重新扫码后保留影片输入与中断位置，重新解析同一剧集再播放。
- 若提示找不到 mpv，可从 [mpv 官方安装页](https://mpv.io/installation/)取得 Windows 版本，并通过 `-MpvPath` 指定或设置 `DOWNKYI_MPV_PATH`。本地验证采用 mpv 官方 CI 的 Windows full build `v0.41.0-dev-g413ff0b1c`；该开发构建并非稳定版。播放器控制使用仅本机的随机命名管道，不开放网络控制端口。
- 房间邀请码应仅发给观影成员；邀请不包含 Cookie、二维码秘密或真实媒体 URL。服务离线、房主离线和成员缓冲会在窗口中显示；房主重连后需要再次点击播放。

## 验证边界

本次已完成 Windows Release 解决方案构建、精确轨道选择测试、房间双 WebSocket 连接信令检查、观影窗口启动、房间 `/health` 检查，以及 mpv 命名管道连接与命令响应检查。还使用本机已有登录会话解析了测试影片 `ep251429`，实际播放了返回的 1080p 音视频轨，确认播放器解码为 1920 × 1080、音频为 48 kHz。采用中质量 AAC 音轨时，两次播放均完成 120 秒前跳，并完成回跳到 10 秒、远跳到 1800 秒，随后持续播放；最高质量 AAC 音轨在本机多次卡在跳转中，因此在线播放在两条轨同时存在时默认中质量，独立观影窗口仍允许手动选高质量。控制通道使用无 BOM 的 UTF-8，避免首条命令被 mpv 忽略而导致启动超时、窗口关闭。

当前会话对该影片最高只返回质量 ID 80，因此**没有**验证真实 4K 音画，也不能保证所有影片的音轨都有相同的跳转表现。尚无第二台设备和公网 `wss` 服务，也没有验证真实双端媒体时间差。使用时最短验收步骤是：两端分别扫码并解析指定影片，确认各自播放器解码尺寸和声音；在一端拖动到未缓冲位置并跳回；加入同一房间，观察房主暂停、恢复、跳转及断线重连后的媒体时间差；退出后检查无残留 mpv 进程或完整影片文件。不能把本机信令检查当成真实异地观影通过。
